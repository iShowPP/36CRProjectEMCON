🛡️ EMCON: four shields, one extension

Every check below is deterministic and anyone can verify it: blind signatures, Ed25519, W3C Verifiable Credentials, structural hashing, time-locks. Nothing depends on a probabilistic "AI detector" that attackers can learn to fool.

Setup (2 minutes)

  1. Server is running if you can read this. (npm start)
  2. Chrome or Edge → chrome://extensions → enable Developer mode → Load unpacked → choose the extension/ folder.
  3. Click the 🛡️ toolbar icon → Ghost → Set up Ghost.

👻 1 · Ghost Engine

Sign up anywhere as a verified human (and optionally 18+) without an email, phone or cross-site ID. A different, unlinkable pseudonym on every site.

Try ShopNorth sign-in…as a "different company"
  • Who vouches for "over 18"? A self-made proof proves nothing. A one-time issuer attests it with blind RSA signatures, so it can't track where the tokens get spent.
  • Sybil farms: single-use tokens and a monthly quota per verified human.
  • Issuer tagging users: issuer keys are pinned and checked for consistency.
  • Phishing relay: every sign-in is signed over the real origin (taken from Chrome, not the page).
  • Fingerprint "randomisation" makes you more unique. Instead, noise is stable per site, high-entropy values are bucketed, and screen/locale are never faked.

🖼️ 2 · Media provenance

Asks "who published this, and has it been changed?" rather than "is this AI?". Badges show up on any site.

Provenance studioSocial feed
  • Platforms strip metadata: a perceptual-hash registry recovers provenance, and the badge links to the original so you can compare.
  • "Unsigned = fake" is false and harmful. Unsigned images get no badge. Only positive evidence or tampering is shown.
  • Copy a real signature onto an edited photo: the hash covers the pixels, so the edit is caught as "Altered".
  • Anyone can sign: only keys on the trust list count as "Verified".

🏦 3 · Honey-Vault

Scam brakes for payments: risk-scaled cooling-off, scam-script check-in, guardians, duress PIN, panic freeze.

Open Kestrel Bank
  • "Just wait 15 min" is easy to coach around. The delay scales with risk, the release needs a check-in, and red flags go to guardians.
  • Thief switches off the protections first: loosening a setting is time-locked and announced to guardians.
  • Duress PIN must not visibly fail: the whole session becomes a consistent decoy.
  • On-chain duress leaks: the Solidity vault covers the time-locks, and duress stays off-chain.

🕸️ 4 · Web of Trust

Domains are rated by signed attestations from people and groups you trust, plus a structural check for brand clones.

  • Fake-review Sybils: only identities reachable from your own trust roots count, and each root's branch is capped.
  • Lookups would leak your browsing: the server only ever sees a 5-hex-char hash prefix (k-anonymity).
  • Compromised relay: every credential is re-verified in your browser.
  • Generic login pages look alike: a clone needs a structure match and a brand mention or credential form on a non-official domain.
